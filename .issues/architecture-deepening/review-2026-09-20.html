Problem
Four suppression reasons — Archived (SQL), Picked, Rejected, Closed — live in four modules, and the order the last two apply in is load-bearing but recorded only in prose.
Solution
One module takes the Selected day and returns the day's partition: picker rows, decided rows, rejected rows, closed rows. Tonight and AI search both read it.
  • Locality: one module owns suppression
  • Filter order becomes testable
  • Leverage: two callers, one interface
  • Page drops to wiring
  • Double rankTonight hides inside
  • Interface is the test surface
Compatible with ADR-0003 and ADR-0010: suppression stays a presentation filter over a pure ranking, and no Score moves. The module is the place that fact finally gets asserted.
Open question for the grilling
The same predicate has opposite consequences today: Tonight keeps closed Restaurants in the Closed disclosure with full controls; AI search removes them from idByIndex so the model cannot return them. Deliberate per ADR-0010, but nothing records it.

Top recommendation

1. One module answers “is this Option choosable on day D?”

Deepening it makes the filter order assertable, gives AI search and Tonight the same answer by construction, and leaves candidate 2 a much smaller job.
